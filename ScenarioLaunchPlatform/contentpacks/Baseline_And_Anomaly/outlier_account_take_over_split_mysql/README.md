# Outlier Account Takeover Split - MySQL

## Overview

This folder contains a **script generator** that creates two separate scripts for simulating an Account Takeover (ATO) outlier pattern in MySQL:

1. **Baseline Script** (Hours 1-4): 50 SELECT queries per hour on `ato_object1` only (single object access)
2. **Anomaly Script** (Hour 5): 100 SELECT queries on each of 5 objects (500 total) via **Java JDBC** (multi-object access spike)

The anomaly simulates an account takeover where a user suddenly accesses many more objects than usual, using a different connection method (JDBC) to further distinguish the anomalous behavior.

Both generated scripts automatically use the **same unique user and database**.

---

## How It Works

```
generate_scripts.sh
       │
       ├──► baseline_TIMESTAMP.sh   (Hours 1-4: 50 SELECTs/hour on ato_object1)
       │         └── Creates unique DB + user
       │         └── Creates 5 tables (ato_object1 to ato_object5)
       │         └── Runs via mysql CLI in background
       │
       └──► anomaly_TIMESTAMP.sh    (Hour 5: 100 SELECTs × 5 objects via Java JDBC)
                 └── Uses same DB + user as baseline
                 └── Generates hour5_selects_TIMESTAMP.sql
                 └── Executes via Java JDBC (java_executor/)
                 └── Runs in background automatically
```

## Prerequisites

- MySQL client (`mysql`) installed and in PATH
- Java JDK/JRE installed (`java` command available)
- `mysql-connector-j-8.0.33.jar` in `java_executor/` folder
- `MySQLSQLExecutor.class` compiled (or run `./java_executor/compile.sh` first)

### Compile Java Executor (if needed)

```bash
cd java_executor
./compile.sh
cd ..
```

## Usage

### Step 1: Generate the Scripts

```bash
chmod +x generate_scripts.sh
./generate_scripts.sh <host> <port> <root_password>
```

**Example:**
```bash
./generate_scripts.sh localhost 3306 MyRootPassword123
```

This will generate two scripts with matching timestamps:
- `baseline_20240215_143022.sh`
- `anomaly_20240215_143022.sh`

### Step 2: Run the Baseline Script

```bash
./baseline_TIMESTAMP.sh
```

- Runs **automatically in the background** (no arguments needed)
- Creates a unique database and user
- Creates 5 tables (`ato_object1` to `ato_object5`) with test data
- Executes 50 SELECT queries per hour on `ato_object1` for 4 hours
- Total duration: ~4 hours

### Step 3: Run the Anomaly Script

After the baseline completes (or while it's running for the last hour):

```bash
./anomaly_TIMESTAMP.sh
```

- Runs **automatically in the background** (no arguments needed)
- Uses the **same database and user** as the baseline
- Generates a SQL file with 500 queries (100 per object × 5 objects)
- Executes via **Java JDBC** (different connection method = anomaly signal)

## Access Pattern

| Hour | Script   | Queries | Objects Accessed | Method    | Pattern   |
|------|----------|---------|------------------|-----------|-----------|
| 1    | Baseline | 50      | ato_object1 only | mysql CLI | Normal    |
| 2    | Baseline | 50      | ato_object1 only | mysql CLI | Normal    |
| 3    | Baseline | 50      | ato_object1 only | mysql CLI | Normal    |
| 4    | Baseline | 50      | ato_object1 only | mysql CLI | Normal    |
| 5    | Anomaly  | 500     | All 5 objects    | Java JDBC | **SPIKE** |

### Why This Detects Account Takeover

- **Normal behavior**: User accesses only `ato_object1` (50 queries/hour)
- **Anomaly**: User suddenly accesses all 5 objects (100 queries each = 500 total)
- **Different client**: Java JDBC vs mysql CLI — different connection fingerprint
- **Volume spike**: 50 → 500 queries in one hour (10× increase)

## Generated Script Details

### Baseline Script
- **Database**: `ato_TIMESTAMP_db` (unique per generation)
- **User**: `ato_TIMESTAMP_user` (unique per generation, SELECT only)
- **Operations**: 50 SELECTs/hour × 4 hours = 200 total queries on `ato_object1`
- **Sleep**: 1 hour between batches
- **Execution**: Always runs in background via `nohup`

### Anomaly Script
- **Database**: Same as baseline (`ato_TIMESTAMP_db`)
- **User**: Same as baseline (`ato_TIMESTAMP_user`)
- **Operations**: 100 SELECTs × 5 objects = 500 total queries
- **Method**: Java JDBC via `java_executor/`
- **Execution**: Always runs in background via `nohup`

---

## Notes

- Each run of `generate_scripts.sh` creates a **new unique pair** of scripts
- The baseline script **creates** the database, user, and all 5 tables
- The anomaly script **reuses** the same DB/user and executes via Java JDBC
- The anomaly script will fail if the baseline has not been run first
- `db.properties` in `java_executor/` is auto-generated by the anomaly script with the correct credentials
